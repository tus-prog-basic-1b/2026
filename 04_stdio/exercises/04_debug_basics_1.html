デバッグの基本（その1）：コンパイルエラーと警告¶

バグとデバッグ¶

プログラムの誤りをバグ（bug）と呼び、バグを見つけて取り除く作業をデバッグ（debug）と呼びます。 プログラムをデバッグするとき、怪しそうなところを思いつきで書き換えても、なかなかバグは直りません。バグを効率よく見つけて直すために、手がかりを集めて原因を推定し、直して、直ったことを確かめる、という決まった手順があります。 この資料では、コンパイル時に見つかるエラーや警告を例に、デバッグの手順と考え方を説明します。

コンパイラのメッセージを読む¶

デバッグでは、まずコンパイラが表示するメッセージを読みます。コンパイラのメッセージが、バグを見つける大きな手がかりになるためです。 コンパイラは、プログラムを機械語に翻訳するときに文法などを確認し、問題があればメッセージを表示します。メッセージには次の2種類があります。

種類 状態
エラー（error） 文法などが正しくなく、実行ファイルを作れない
警告（warning） 実行ファイルは作れるが、誤りの可能性が高い

メッセージは、誤りが見つかった場所と内容を教えてくれます。次のプログラムは、5行目の末尾に ; がありません。

price.c

3

5

7
8
#include <stdio.h>

int main(void)
{
    int price = 120
    printf("%d\n", price);
    return 0;
}

$ gcc -Wall -Wextra price.c -o price
price.c:5:20: error: expected ';' at end of declaration
    5 |     int price = 120
      |                    ^
      |                    ;
1 error generated.

先頭の price.c:5:20 は「price.c の5行目、20文字目」、error はエラーであること、その後ろが内容（「宣言の終わりに ; が必要」）を表します。 エラーメッセージの読み方と単語の意味は、第2回の講義資料「エラーメッセージ」も参照してください。

メッセージを読んだら、示された場所と内容から原因を推定して、コードを直します。原因が分からないまま書き換えると、もともと正しかった部分まで壊してしまうことがあります。

注意：メッセージの文面は、コンパイラの種類や版によって異なります。この資料では、コマンドは演習と同じ gcc の形で示していますが、メッセージの例は clang の出力です。WSL の gcc では言い回しや示される位置が少し違いますが、場所と内容を示すことは同じです。

指摘された行と、その直前の行を見る¶

メッセージが示す行に、原因があるとは限りません。たとえば ; の抜けは、コンパイラによっては「次の行の先頭で、予期しないものが現れた」として、次の行のエラーとして報告されます。 コンパイラは、誤りに気づいた時点の場所を報告するためです。示された行に誤りが見当たらないときは、その直前の行も確認します。

最初のメッセージから直す¶

1つの誤りが、多数のメッセージを引き起こすことがあります。次のプログラムは、7行目の printf で、文字列を閉じる " を書き忘れています。

quote.c

10
#include <stdio.h>

int main(void)
{
    int price = 120;

    printf("%d\n, price);
    printf("done\n");
    return 0;
}

$ gcc -Wall -Wextra quote.c -o quote
quote.c:7:12: warning: missing terminating '"' character [-Winvalid-pp-token]
    7 |     printf("%d\n, price);
      |            ^
quote.c:7:12: error: expected expression
quote.c:10:2: error: expected '}'
   10 | }
      |  ^
quote.c:4:1: note: to match this '{'
    4 | {
      | ^
1 warning and 2 errors generated.

警告1件とエラー2件が表示されますが、原因は7行目の1か所だけです。3件目のエラーは、原因から離れた10行目を指しています。7行目を printf("%d\n", price); に直すと、すべてのメッセージが消えます。 このように、後ろのメッセージは最初の誤りの「巻き添え」であることが多いため、最初に表示されたメッセージから直します。メッセージがたくさん出ても、一つずつ順に見ていけば、実際に直す箇所は少ないことがよくあります。

一度に1か所だけ直す¶

怪しい箇所が複数あっても、一度に直すのは1か所にします。 まとめて書き換えると、エラーが消えたとしても、どの修正が効いたのか分かりません。逆に新しいエラーが出たときも、どの修正で入れてしまったのか分からなくなります。1か所ずつ直せば、修正と結果の因果関係がはっきりし、次に同じ誤りをしたときにも原因にすぐ気づけます。

直すたびに保存して、コンパイルし直す¶

ソースファイルを直しても、実行ファイル（price や a.out）は自動では更新されません。保存してからコンパイルし直さないと、古いプログラムを実行し続けることになり、「直したのに結果が変わらない」と誤解してしまいます。 修正したら、保存 → コンパイル → 実行をひと組にして繰り返します。

警告も直す¶

警告が出ても、実行ファイルは作られます。しかし、警告は「書いたとおりには動くが、意図とは違う可能性が高い」ことを知らせています。次のプログラムは、float 型の変数を %d で表示しようとしています。

weight.c

1
2
3
4
5
6
7
8
9
#include <stdio.h>

int main(void)
{
    float weight = 52.5;

    printf("%d\n", weight);
    return 0;
}

$ gcc -Wall -Wextra weight.c -o weight
weight.c:7:20: warning: format specifies type 'int' but the argument has type 'float' [-Wformat]
    7 |     printf("%d\n", weight);
      |             ~~     ^~~~~~
      |             %f
1 warning generated.
$ ./weight
90538872

コンパイルは通りますが、表示される値はでたらめです（値は実行環境によって変わります）。警告を無視すると、このような誤りが実行時まで残ります。誤りの種類によっては、実行中にプログラムが異常終了する（Segmentation fault などと表示される）こともあります。実行時のエラーの例は、第2回の講義資料「エラーメッセージ」も参照してください。 演習で使うコンパイルのオプション -Wall -Wextra は、このような警告をできるだけ多く表示させるためのものです。エラーだけでなく、警告もすべてなくすことを目標にします。

最後に、実行して仕様と比べる¶

エラーと警告がなくなっても、プログラムが正しく動くとは限りません。最後に実行し、課題の実行例（期待する結果）と実際の結果を比べます。結果が違う場合の調べ方は、その2で説明します。
