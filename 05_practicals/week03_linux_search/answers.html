第3回：ファイルとログの検索（解答例）¶

問題へ

find・wcを使う調査¶

以下に示す検索結果の順序は一例である。findや再帰的なgrepの表示順は実行環境によって異なるため、順序ではなく表示された項目と件数を確認する。

1. ディレクトリ構成の把握¶

$ find starter -type d

starter
starter/data
starter/logs
starter/programs

-type dは、検索対象をディレクトリに限定する指定である。登録情報はdata/、コンパイルログはlogs/、Cソースファイルはprograms/にあることが分かる。

2. Cソースファイルの全体像と件数の把握¶

$ find starter -type f -name "*.c"
$ find starter -type f -name "*.c" | wc -l

starter/programs/broken.c
starter/programs/calc.c
starter/programs/hello.c
starter/programs/zodiac.c
4

-type fは検索対象をファイルに限定し、-name "*.c"は名前が.cで終わるファイルを指定する。1つ目のコマンドの出力を|でwc -lに渡すことで、Cソースファイルが4個あることを確認できる。

grepを使う調査¶

3. 登録状態と正規表現による検索結果の違いの確認¶

$ grep '^m' starter/data/components.csv

小文字のmで始まる、hello.cとcalc.cの2行が表示される。

$ grep -i '^m' starter/data/components.csv

-iによって大文字・小文字を区別しないため、上記2行に大文字のMで始まるbroken.cを加えた3行が表示される。

$ grep '^m24[0-9][0-9][0-9],' starter/data/components.csv

小文字のm24で始まり、その後に数字が3文字続く、hello.cとcalc.cの2行が表示される。末尾の,は、数字が3文字で終わる位置を明確にするための指定である。

$ grep 'review$' starter/data/components.csv
$ grep 'blocked$' starter/data/components.csv

$は行末を表す。reviewで終わる行にはcalc.cとzodiac.c、blockedで終わる行にはbroken.cが登録されている。したがって、課題の条件であるreviewを満たす候補はcalc.cとzodiac.cである。

4. 出力処理の場所の把握¶

$ grep -rn "printf" starter/programs

starter/programs/calc.c:10:    printf("%d\n", a + b);
starter/programs/hello.c:6:    printf("Hello\n");
starter/programs/zodiac.c:11:        printf("Monkey\n");
starter/programs/zodiac.c:14:        printf("Other\n");

-rはディレクトリ内を再帰的に検索し、-nは行番号を表示する。printfの検索によって、3つのCソースファイルに出力処理があることと、その場所を確認できる。broken.cのprontfは綴りが異なるため表示されない。

5. 標準入力を使用するCソースファイルの特定¶

$ grep -rl "scanf" starter/programs

starter/programs/calc.c
starter/programs/zodiac.c

-lは、一致した行ではなくファイル名だけを表示する。標準入力を使用するという条件を満たす候補はcalc.cとzodiac.cである。

6. 未完了の作業を示す記述があるCソースファイルの特定¶

$ grep -rnE "TODO|FIXME" starter/programs

starter/programs/calc.c:8:    // TODO: 入力エラーの処理を後で追加する
starter/programs/zodiac.c:7:    // FIXME: 12種類の表示は次回以降に完成させる

-Eを付けると、|で複数の検索文字列を指定できる。TODOまたはFIXMEを含むという条件を満たす候補はcalc.cとzodiac.cである。

7. 問題が記録されたログとCソースファイルの特定¶

$ grep -in "warning" starter/logs/*.log
$ grep -in "error" starter/logs/*.log

-iによって大文字・小文字を区別せず、-nによって行番号付きで検索する。warningはcompile02.logにあり、ログ本文からcalc.cに対応することが分かる。errorはcompile03.logにあり、broken.cに対応することが分かる。

これらは検索演習用の模擬ログである。使用するGCCのバージョンや環境によっては、Cソースを実際にコンパイルしたときの診断内容と異なる場合がある。

参考：条件を照合する考え方¶

特定したCソースファイルはcalc.cである。

  • components.csvにおける状態がreview
  • scanfによる標準入力の使用
  • TODOの記載
  • 対応するcompile02.logにおける警告

zodiac.cは最初の3条件を満たすが、対応するログに警告またはエラーがない。broken.cにはエラーがあるが、状態がblockedであり、scanfやTODO、FIXMEもない。そのため、すべての条件を満たすファイルはcalc.cだけである。

使用したコマンドの概要は、名前や種類による検索にfind、件数の集計にwc -l、ファイル内容の検索にgrepを使用したことである。grepでは、必要な表示形式や検索条件に応じて-i、-n、-r、-l、-Eと正規表現を使い分けた。
