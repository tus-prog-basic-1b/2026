デバッグの基本（その3）：デバッガで動きを追う¶

その2では、期待結果と実際の結果を比べ、途中の値を printf() で表示して原因を絞り込みました。 繰り返し処理では、同じ部分が何度も実行され、変数の値が反復ごとに変わります。どの反復で意図と違う値になったかを調べる必要があるため、結果だけを見ても原因が分かりにくくなります。 この資料では、繰り返し処理で起きやすい異常と、デバッガを使って動きを追う方法を説明します。デバッガの操作方法は、VS Codeデバッグガイドを参照してください。

終わらないプログラムを止める¶

繰り返しの条件が満たされ続けると、プログラムが終わらなくなります（無限ループ）。 端末で実行していて終わらなくなったときは、Ctrl+C を押して強制終了します。そのうえで、なぜ条件が満たされ続けたのかを調べます。

なぜデバッガを使うのか¶

printf() で値を表示する方法は手軽ですが、繰り返し処理では表示が反復の回数だけ増え、どこを見ればよいか分かりにくくなります。また、確かめたい変数が変わるたびに、ソースを書き換えてコンパイルし直す必要があります。 デバッガを使うと、ソースを書き換えずに、指定した行でプログラムを一時停止させ（ブレークポイント）、1行ずつ実行しながら、その時点のすべての変数の値を確かめられます。反復ごとに値がどう変わるかを、順に追うことができます。

デバッガで変数名や行番号を使うには、コンパイルするときに -g を付けて、そのための情報を実行ファイルに含めます。演習で配布する VS Code の設定（.vscode）では、ビルドするときに自動で付きます。端末でコンパイルする場合は、次のように指定します。

$ gcc -std=c11 -Wall -Wextra -pedantic -g trace.c -o trace

期待する値の変化を先に書き出す¶

その2で期待結果を先に決めたのと同じように、繰り返し処理では、各反復で変数がどう変わるはずかを先に表に書き出します。そのうえでデバッガで実際の値を確かめ、最初に食い違った反復を探します。

#include <stdio.h>

int main(void)
{
    int sum = 0;

    for (int i = 1; i <= 3; i++) {
        sum = sum + i * 2;
    }
    printf("%d\n", sum);
    return 0;
}

sum = sum + i * 2; の実行前と実行後の値は、次のようになるはずです。

反復 i 実行前の sum 実行後の sum
1回目 1 0 2
2回目 2 2 6
3回目 3 6 12

4回目に条件 i <= 3 を判定するときは i が 4 になっていて、条件を満たさないので繰り返しを終えます。 このような表と、デバッガで見た実際の値を、反復ごとに比べます。最後の反復では i = 3 を確認し、Step Overでループ後の printf 行まで進んで sum = 12 を確認します。更新と条件判定はソース行単位の操作では分けて観察できるとは限らないため、終了判定時の i = 4 は処理の流れから考えます。i は for 内で宣言されているため、ループ後には参照できません。

デバッガで見るところ¶

繰り返し処理の誤りは、次の場所に現れやすいため、ここで一時停止して値を確かめます。

見るところ 理由
繰り返しに入る前の、合計などを入れる変数の初期値 初期値が誤っていると、すべての反復の計算がずれるため
1回目の反復を終えたときの値 計算式そのものの誤りは、最初の反復ですぐ現れるため
1回の反復で変わるはずの値（i など） 変化しない、または変化の仕方が違うと、終わらなかったり回数が変わったりするため
ループ本体で停止したときの変数と継続条件 その反復が実行される条件を満たしているか確認するため
最後の反復のループ変数と、ループ後の合計など 上限付近の値と最終結果を比べ、反復が1回多い・1回少ないという誤りを調べるため

警告も含めてコンパイラのメッセージを確かめること、一度に1か所だけ直すこと、直したら保存してコンパイルし直すこと（その1）、修正後はもう一度テスト値で確かめること（その2）は、ここでも同じです。
