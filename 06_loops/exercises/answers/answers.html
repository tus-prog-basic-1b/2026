第6回：デバッガで追う繰り返し処理（解答例）¶

問題へ

修正と確認の進め方¶

各反復で期待する変数の値を先に考え、VS Codeデバッグガイドの手順で観察する。ブレークポイントで止まった時点では、その行はまだ実行されていない。Step Overで一行進め、実行後の値と比較する。警告も確認し、原因を調べて1箇所ずつ修正する。修正したら保存して再ビルドし、出力と終了動作を確かめる。

課題1は変更不要である。課題3は無限ループになるため、調べる前にStopで実行を止める方法を確認しておく。端末でコンパイルする場合は、starter フォルダで次のように実行する。

$ gcc -std=c11 -Wall -Wextra -pedantic -g trace_demo.c -o trace_demo
$ ./trace_demo

課題1：trace_demo.c¶

正常なプログラムなので変更しない。sum = sum + i; にブレークポイントを置く。停止した時点では加算はまだ実行されていない。Step Overで加算を実行し、次の値と比較する。

反復 i 加算前の sum 加算後の sum
1回目 1 0 1
2回目 2 1 3
3回目 3 3 6 
#include <stdio.h>

int main(void)
{
    int sum = 0;

    for (int i = 1; i <= 3; i++) {
        sum = sum + i;
        printf("i=%d, sum=%d\n", i, sum);
    }
    return 0;
}

実行結果は次のとおり。

i=1, sum=1
i=2, sum=3
i=3, sum=6

課題2：off_by_one.c¶

sum = sum + i; にブレークポイントを置く。修正前は最後の反復で i = 4 となる。そこからStep Overでループ後の printf 行まで進み、sum = 10 を確認する。i < 5 を i <= 5 に修正し、最後の反復で i が5、ループ後に sum が15となることを同じ手順で確認する。

処理の流れとしては、修正前は i が5に、修正後は6に更新された時点で継続条件が偽になり、ループが終了する。ただし、ソース行単位のStep Overでは、更新と条件判定の間に停止できるとは限らない。for の行で停止しても、更新前の値が表示される場合がある。また、i は for 内で宣言されているので、ループ後には参照できない。そのため、ループ終了時の i の値は確認しなくてよい。最後の反復の i とループ後の sum を観察すればよい。

#include <stdio.h>

int main(void)
{
    int sum = 0;

    for (int i = 1; i <= 5; i++) {
        sum = sum + i;
    }
    printf("%d\n", sum);
    return 0;
}

実行結果は次のとおり。

15

課題3：infinite_loop.c¶

修正前は i が1から変わらない。while の本体の printf の行にブレークポイントを置き、同じ値が繰り返されることを確認したらデバッガのStopで停止する。端末で直接実行した場合は Ctrl+C で停止する。修正として、ループ本体の末尾に i++; を追加する。修正後は1〜5を一度ずつ表示し、i が6になった時点でループを抜ける。

#include <stdio.h>

int main(void)
{
    int i = 1;

    while (i <= 5) {
        printf("%d\n", i);
        i++;
    }
    return 0;
}

実行結果は次のとおり。

1
2
3
4
5

課題4：factorial_init.c¶

修正前は最初の乗算後も product = 0 のままである。0に何を掛けても0なので、product の初期値を1にする。修正後は、乗算のたびに product が1、2、6、24、120と変わる。

#include <stdio.h>

int main(void)
{
    int product = 1;

    for (int i = 1; i <= 5; i++) {
        product = product * i;
    }
    printf("%d\n", product);
    return 0;
}

実行結果は次のとおり。

120

課題5：even_count.c¶

if (i % 2 == 0); の末尾のセミコロンは空文になり、直後のブロックは条件と関係なく毎回実行される。警告を確認し、不要なセミコロンを削除する。デバッガで、i が偶数の反復でだけ count が増えることを確認する。

#include <stdio.h>

int main(void)
{
    int count = 0;

    for (int i = 1; i <= 10; i++) {
        if (i % 2 == 0) {
            count++;
        }
    }
    printf("%d\n", count);
    return 0;
}

実行結果は次のとおり。

5

課題6：fizzbuzz_debug.c¶

上限を i < 21 から i <= 21 に直し、21まで繰り返す。15の倍数は3の倍数でもあるため、3の倍数を先に判定すると FizzBuzz の分岐に到達しない。15の倍数の判定を最初に置く。二つの問題は一つずつ直して、そのつど再ビルドする。デバッガで i が15のときに進む分岐と、最後の反復で i が21になることを確かめ、21行の出力を期待出力と比べる。

#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 21; i++) {
        if (i % 15 == 0) {
            printf("FizzBuzz\n");
        } else if (i % 3 == 0) {
            printf("Fizz\n");
        } else if (i % 5 == 0) {
            printf("Buzz\n");
        } else {
            printf("%d\n", i);
        }
    }
    return 0;
}

完了時の確認¶

課題で使用した6ファイルがすべて作業場所にあり、それぞれ警告なくコンパイルでき、指定された出力と終了動作を満たすことを確認する。trace_demo.c の加算前後の値を説明し、修正した infinite_loop.c が正常終了することを確かめる。確認後はTAに報告し、主に課題6の fizzbuzz_debug.c の上限と条件順序の修正内容、実行結果、デバッガで確認した変数値を説明する。
